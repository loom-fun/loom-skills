## 1. Summary

Published service ABI 1 and the legacy HAL signatures stay accepted, so this release needs no source rewrite: there is no `rewrite_v020_v030.py` and none is needed. Measured on the control and
target sweep ([run 45252435739](https://github.com/loom-fun/loom-skills/actions/runs/45252435739): `sweep.py` under 0.2.0 and 0.3.0, identical diagnostics under both): 61 frozen production
revisions parse and link the same under both SDKs except two pre-existing cases, and 55 programs-only kit builds parse with 0 failures. What the release changes is at load time, in defaults and
in telemetry; those are found only by DevLab sessions (section 5).

| Severity | Change | Fleet impact |
|---|---|---|
| N/A (HARD load only for an unversioned development controller) | bare unversioned controller exports now select ABI 2 (`_v2`); a published `"version": 1` service runs unchanged | 0 of 55 kit packages (the kit emits `"version": 1`); 0 production repos; the library's ABI 2 presets belong to the Flash-Next lane |
| SILENT | a version-1 `publish_epoch` without the new `%proposal_counts` buffer reports proposals as unknown: `/metrics` drops `draft_proposed_tokens`, so no acceptance row | every drafted package (kit default restores it; frozen programs use the harness fallback) |

Sweep numbers (control = 0.2.0 on the same trees): frozen production, 61 packages: 1 package fails to parse under both SDKs (the manual Inkling R9700 card, six files, STRUCTURE/034 pure-effect

## 2. Breaking changes

### 2.1 Controller ABI: bare exports are ABI 2, version-1 packages run unchanged (upstream #3528)
- **Class**: program ABI. **Severity**: N/A for every package in the fleet; HARD load only for a development controller with unversioned exports.
- **Before / after**: 0.2.0 selected service `"version": 1` and bare names also meant ABI 1 (prepared capacity shapes; `publish_epoch` ending in `%progress: buffer`). 0.3.0 accepts ABI 1 unchanged,
  adds ABI 2 (`_v2` exports, token/span limits at `prepare`, exact live counts per packet, `%proposal_counts: buffer` appended to `publish_epoch`) and makes bare unversioned names follow ABI 2:

      - %first_results: buffer, %next_results: buffer, %progress: buffer)
      + %first_results: buffer, %next_results: buffer, %progress: buffer, %proposal_counts: buffer)

  One server hosts ABI 1 and ABI 2 models together; the loader reads each linked export signature once and loads a small capacity adapter only for ABI 1.
- **Touches**: kit templates `skills/loom-port-llm/starter/templates/control.loom:2564` (`@publish_epoch`) and `templates/service.loom:237-244` (decl, `text_publish_epoch`, the `_v1` wrapper); the kit's card
  has `"services": {"chat": {"kind": "text", "version": 1}}` (`starter/build.py:980`). Every published package selects version 1: 0 files change. Library catalogs (Flash-Next, dense 27B) opt into ABI 2 at
  the library tag: that is lane #1417, not a migration step.
- **Step**: none for a package that selects version 1. A hand-written controller with unversioned exports: either suffix each role `_v1` and select `"version": 1`, or port the whole service to `_v2`.
- **Verify**: serve and exercise every changed service (a chat, a tool call; an image for an encoder). `sweep.py` cannot see this: the signature is checked at load.

### 2.2 Speculative telemetry: proposal counts (upstream #3360)
- **Class**: program ABI and request semantics. **Severity**: SILENT.
- **Before / after**: 0.2.0 summed proposals from the configured depth. 0.3.0 reports the candidates actually presented; a version-1 publisher that omits `%proposal_counts` reports `proposed_tokens: null`,
  and a single unknown span makes `/metrics` drop `draft_proposed_tokens` for the server's lifetime. The epoch events replace `token_slots`/`token_capacity`/`span_capacity` with `scheduled_tokens`.
  0.3.0 accepts a 14-argument version-1 `publish_epoch` (`control.c`), so no ABI 2 port is needed to restore the counter.
- **Touches**: kit choice `telemetry.proposal_counts` (`skills/loom-kb/choices.py:779`, `starter/proposal_counts.py`, `starter/build.py:884-886`; default on); readers of the counter
  `skills/loom-benchmark/scripts/spec_check.py:176`, `scripts/draft_telemetry.py:5`, `.github/scripts/ab_decode.py:38,53`, and the card acceptance rows (`make_info.py perf --draft-metrics`). Frozen
  production programs cannot get the 14th buffer (they stay byte-identical): use the decode request's counter deltas to compute accepted drafted tokens per verification pass (section 9).
- **Step**: kit programs: nothing to do (default on). A hand-written publisher: append the buffer (one little-endian u32 per first-packet span, zero for ordinary work). Readers: treat a missing proposal counter as unknown, never derive it from depth.
- **Verify**: `/metrics` of a drafted package after a decode shows `draft_proposed_tokens`; acceptance equals the 0.2.0 card (section 6).

### 2.3 HAL ownership contract (upstream #3415)
- **Class**: program ABI. **Severity**: N/A.
- **Before / after**: owning `hal.buffer` / `hal.fence` / `hal.file` signatures (0.2.0) vs borrowed `ptr<@Hal...>` and owning `ref<@Hal...>` (0.3.0); the loader binds both ("a serving-boundary choice, not a global rewrite").
- **Touches**: the kit's templates use the legacy signatures (18 `hal.buffer` lines in `skills/loom-port-llm/starter/templates`); nothing changes.
- **Step**: none; keep the legacy signatures. A port to explicit ownership must pair each owner's last use with `ref.release`. **Verify**: serve (the loader links the legacy contract).

### 2.4 SDK pin and install (stable release on PyPI)
- **Class**: install and pin. **Severity**: INSTALL.
- **Before / after**: `pip install hrx-loom==0.2.0` and pin `{"hrx_loom": "0.2.0", "source": "pypi", ...}`; now `pip install hrx-loom==0.3.0` (card Quick start `pipx install "hrx-loom[hf]==0.3.0"`) and pin
  `{"hrx_loom": "0.3.0", "source": "pypi", "wheel_sha256": "6252bb0d...", "hrx_system_sha": "e2c41a72..."}`; the catalog association is the tag `v0.3.0`. A package with no pin still means 0.1.0.
- **Touches**: `skills/loom-setup/scripts/install_loom.sh:23` (default 0.3.0), `sdk_pin.py:31` (`VERIFIED_RELEASES["0.3.0"]`), `sdk_pin.py:41,46` (`newest_verified`, `release_pin`), `fleet/regen.py:122`
  (`SDK_NEW = sdk_pin.newest_verified()`), card Quick start (`skills/loom-benchmark/scripts/card/render_card.py`), `.github/nightly-models.json` and CI install steps (through `ensure_sdk.sh`), starter kit pins,
  and the `sdk` block of every frozen package's `llm_config.json` (the migration's only data change). The kit emits the pin itself (#1434): there is no post-hoc stamp (`stamp` for a hand-made package also writes `"branch": "v0.3.0"`, see 3a step 4).
- **Step**: hand edit of the installer and pin files (landed); `sdk_pin.py stamp ROOT llm_config.json` for a package you own. **Verify**: `ensure_sdk.sh` picks 0.3.0 for a 0.3.0 pin and 0.2.0 for a 0.2.0 pin; `loom-serve --version` prints `0.3.0 (commit e2c41a72...)`.

### 2.5 Parameter loading: `file` is the default, `preload` and `--materialize=copy` are gone (upstream `parameter_util.c`)
- **Class**: install/deployment and card Quick start. **Severity**: HARD deployment on a stock host (8 MiB `ulimit -l`) for a package that still prints 0.2.0's workaround; otherwise INSTALL.
- **Before / after**: 0.2.0's default mode failed the first request on a stock Ubuntu host (`buffer pin preparation failed (12)`, ROCm/hrx-system#3332), so cards printed `--parameter_mode=preload` (and
  `--materialize=copy` for the fetch) where the host copy of the weights fit. 0.3.0 defaults to `file` (buffered on-demand reads, no pinned io_uring buffers); `direct` is uncached and alignment-bound,
  `debug-preload` is diagnostic. The flag is hidden in `loom-serve --help` in both releases.
- **Touches**: `card_lib.py:822-833` (`PRELOAD_FLAG`, `sdk_uses_file_parameters`, `sdk_serve_args` drop the flag for SDK >= 0.3), `render_card.py:618,944` (`--materialize=copy` only for pins below 0.3 or a
  non-PyPI source), `skills/loom-setup/scripts/serve.sh:50-57`, `fleet/devices/*.json` (`gfx1150.json:17` still carries the 0.2.0 host note; refreshed when that GPU is re-measured),
  `skills/loom-benchmark/scripts/test_9070xt.py`. 0.2.0 cards keep their flag (they run on their own pin).
- **Step**: card renderer (landed); a package you own: drop `--parameter_mode=preload` and `--materialize=copy` from the printed commands once it passes the check. Do not substitute `direct`.
- **Verify**: the rendered Quick start of every GPU on a stock Ubuntu host (default `ulimit -l`, no root). Evidence so far: Qwen3-0.6B on Strix Halo with an 8 MiB memlock
  ([run 45257927036](https://github.com/loom-fun/loom-skills/actions/runs/45257927036)); the per-GPU stock-host check is part of release readiness (#1410).

### 2.6 Elastic backing packs slabs (upstream #3352 #3355 #3427, `--memory_prewarm_bytes` #3475)
- **Class**: device runtime and card (serve flags). **Severity**: SILENT.
- **Before / after**: elastic storage and scratch now take exact logical extents from shared page-sized pieces of larger slabs (upstream: committed backing 3.30 -> 1.49 GiB in a 2,124-token workload; TTFT
  within 0.71 %); `--memory_prewarm_bytes` is new (default 0); `--pool_backing` default stays `elastic`.
- **Touches**: `skills/loom-kb/device/rdna3/strix-halo/device.json:23` (`--pool_backing=fixed`), the R9700 device entry, the `render_card.py` Quick start, `fleet/devices/*.json`.
- **Step**: none; the cards keep `--pool_backing=fixed` (section 7). **Verify**: native-context admission on both GPUs (identical to fixed in runs 45526706622 and 45527602104) and the prefill rows of 5b.

### 2.7 Request surface: count route, launcher routes, typed errors (upstream #3503 #3504 #3508 #3512 #3515 #3521 #3527 #3529)
- **Class**: request semantics. **Severity**: SILENT, additive.
- **Before / after**: `POST /v1/chat/completions/input_tokens` answered 400 beyond the generation window; 0.3.0 measures the complete conversation (framing, tools, images) when `prepare_input` returns no
  tokens plus the count (capacity -1). New: `/health`, `/ready`, `GET /v1/models/{id}`, model-less `/tokenize` and `/detokenize` for one model, `loom-serve --version`, unknown model -> 404 `model_not_found`.
- **Touches**: kit choice `chat.input_measure` (`choices.py:774`, `starter/input_measure.py`, `starter/build.py:881-883`; default on); gates and integrations that probe health or tokenize (Gufo and Lemonade launchers can use `/health`).
- **Step**: kit default (landed, #1449). **Verify**: a count over the window answers a number (54260 for a 40960-token context in run 45527529704); in-window counts equal chat `prompt_tokens`.

### 2.8 gfx12 K/V-once attention regression (a silent slowdown, root-caused)
- **Class**: device runtime. **Severity**: SILENT; the only fleet row that moved beyond the band for a kernel reason found in the pilot.
- **Before / after**: Qwen3.6-35B-A3B on the R9700 served K/V-once attention (`g_attention_split_rdna4`, `decode.attn.kv_once.d256` true). The body takes 427.80 ms on 0.2.0 and 1109.92 ms on 0.3.0 for the 1290
  launches of a 32K decode (2.59x): decode_32k 121.92 -> 83.16 tok/s. The family rule (split attention for drafted qwen35moe, `kv_once.d256` false) gives 121.18 tok/s at 32K and 161.24 vs 161.05 at 2K
  ([run 45297807464](https://github.com/loom-fun/loom-skills/actions/runs/45297807464)).
- **Touches**: `skills/loom-kb/model/ggml-org-Qwen3.6-35B-A3B-loom/scope.json` (the per-GPU rule is removed, #1436), `arch/llm/moe/qwen35moe/scope.json`, `arch/llm/moe/qwen35moe/decode.md`.
  The frozen production program carries the slow body, so the phase-2 kit build must beat it: kit vs frozen on 0.3.0, R9700 decode_32k 84.6 -> 124.9 tok/s (+47.6 %, run 45526213967).
- **Step**: kit rule (landed). **Verify**: the ABBA of decode_32k. Check any other kernel with a high VGPR count or a K/V-once body on gfx12 for the same slowdown.

### 2.9 Windows and standalone limits (measured, no migration)
- **Class**: install and device runtime. **Severity**: HARD deployment for the affected package.
- **Before / after**: a standalone `loom-serve` has no C++ importer (a package that imports C++ needs the wheel); a C++ header loaded at 259 characters of path and failed at 260; Flash-Next on Windows reaches
  `DEVICE_LOST` (gotchas, section 9). **Touches**: Flash-Next package and its card (no kit file). **Step**: use the Linux wheel route for Flash Next. **Verify**: the Windows sample (#1410). Windows speed numbers are in section 6.

## 3. Mechanical steps

### 3a. One package you own (hand-made or catalog; a kit-generated package is regenerated with the kit instead)

Every new shell needs `export LOOM_SKILL_DIR=...` first (SKILL.md, "Bundled paths"); the commands below use it.

1. Install 0.3.0 in a separate root (the wheel digest is checked against the published one):
   `bash "${LOOM_SKILL_DIR}/../loom-setup/scripts/install_loom.sh" ~/loom-0.3.0 0.3.0`.
   The 0.2.0 control is optional for one package (the sweep's pass line is the bar); for a control run
   `bash "${LOOM_SKILL_DIR}/../loom-setup/scripts/install_loom.sh" ~/loom-0.2.0 0.2.0`.
2. Keep a copy of the published package revision and its SDK pin: `git clone https://huggingface.co/ORG/REPO PKG` (or `hf download ORG/REPO --local-dir PKG`; `loom-fetch` without
   `--materialize=copy` yields only a cache, not a package directory). Run the sweep on it (`python3 "${LOOM_SKILL_DIR}/scripts/sweep.py" --sdk ~/loom-0.3.0/.venv PKG --json sweep.json`, and
   with `--sdk ~/loom-0.2.0/.venv` for the control). The pass line is `0 fail to parse, 0 fail to link, 0 link-skipped`; the sweep proves parse and link only, not GPU load. Then serve the same published preset
   with 0.3.0 and exercise text and tools, an image for a vision encoder, or an image request for an image service. Serving needs a GPU: without one only the CPU proofs (sweep) run, and the stamp
   in step 4 stays unproven until a GPU smoke passes.
3. Source needs no rewrite for a published version-1 package. Only an unversioned development controller needs 2.1 (suffix `_v1` and select version 1, or port to `_v2`); a publisher that should report proposals gets 2.2.
4. After the runtime check, stamp the pin: `python3 "${LOOM_SKILL_DIR}/../loom-setup/scripts/sdk_pin.py" stamp ~/loom-0.3.0 PKG/llm_config.json` (a package with an `llm_config.json`); an image
   package without one updates its pinned install instructions after an image request passes. Preserve the model, origin, program and tokenizer files. The stamp copies `loom-install.json`, so the
   resulting pin is exactly `{"hrx_loom": "0.3.0", "source": "pypi", "branch": "v0.3.0", "hrx_system_sha": "e2c41a72...", "wheel_sha256": "6252bb0d..."}` (full digests), and it rewrites the file with
   one-space indent and a trailing newline; the `branch` field is expected (the kit's own pin omits it; `sdk_pin.py` matching does not read it).
5. Drop `--parameter_mode=preload` and `--materialize=copy` from your printed commands and run them on a host with the default `ulimit -l` (2.5). The printed commands are in the package README's
   Quick start (the pipx install pin, the `loom-fetch ... --materialize=copy` line, `--parameter_mode=preload`) and its stale bullet "`--materialize=copy` puts copies of the fetched package files in the output directory": update all four.
6. Leave the `hrx_loom` provenance lines in `REPORT.md` and `info.json` as they are: they record what was measured on the older SDK.

### 3b. The fleet (campaign order, two phases per model; `fleet/README.md` "Frozen SDK migration")

    python3 fleet/sdk_inventory.py snapshot -o /tmp/inv.json && python3 fleet/sdk_inventory.py drift skills/loom-migrate/versions/v0.2.0-to-v0.3.0-production.json /tmp/inv.json
    python3 fleet/regen.py plan --base sdk030 --device strix-halo --device radeon-r9700 --mode sdk-loom --programs production --all --state sdk030.json   # phase 1: frozen programs on 0.3.0
    python3 fleet/regen.py submit sdk030.json --max-inflight auto      # poll >= 120 s with one loop: regen.py poll, collect; rerun + submit for a row outside +-3 %
    python3 fleet/regen.py evidence sdk030.json -o evidence.json       # sdk-evidence/1: the source of section 5b and of eligible.json
    python3 fleet/regen.py package sdk030.json && python3 fleet/regen.py ingest sdk030.json && python3 fleet/regen.py publish sdk030.json   # staging only
    python3 fleet/regen.py plan --base sdk030 --mode sdk-ab --old-sdk target --no-baselines --all --state sdk030-p2.json                       # phase 2: kit build vs frozen, both on 0.3.0, ABBA

Phase 1 ships each model's frozen production programs (program files byte-identical; only the pin and the Quick start change), so a card's delta line is the SDK alone. Phase 2 measures the kit build
(post-0.2.0 kit changes plus each SDK 0.3.0 capability adopted by an A/B) against the phase-1 card; the kit programs ship for a model only where the ABBA is equal or better and every gate passes. Runner-less
GPUs keep their rows marked SDK 0.2.0 with the 0.3.0 Quick start (owner decision 2026-11-24). The card tag rule: `loom-fleet` reference/publish.md "Card tags".

## 5. Verification

- **Fleet proof (CPU)**: the control and target sweep of section 1 (same diagnostics under 0.2.0 and 0.3.0; 55 kit builds, 0 parse failures). The source program diff of the migrated fleet is empty:
  the migration changes the `sdk` pin of `llm_config.json` and the Quick start, never a program. Frozen packages are byte-identical, checked by programs hash in every job (`programs_sha256` equals the production
  card's before anything is measured; `eligible.json` carries it per row).
- **GPU smoke (DevLab)**: serve, one chat, one tool call (and an image) per representative: dense small, hybrid recurrent, vision, MoE, one R9700 job, an image-generation package. The final smoke per GPU on the
  final staging revisions is part of release readiness (#1410).
- **SDK A/B**: phase 1 per model and device, Loom rows only, against the old card's stored rows (rule 17); a row outside +-3 % gets one same-job ABBA (old pin vs new on the same runner). Gates once per job
  (the 8 gates plus the native-context admission probe; no needle gates).
- **Expected program diff classes and counts**: frozen packages: the pin block of `llm_config.json` and the Quick start text only (no program line). Kit packages: the 14th `publish_epoch` buffer and the count-route
  `prepare_input` (two scoped kit defaults, #1449 #1450), whose perf is inside the band (section 6).
