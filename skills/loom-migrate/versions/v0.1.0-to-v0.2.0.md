## 1. Summary

Measured on the 51-package fleet (programs-only build of the v0.1.0 kit, `sweep.py --sdk` the rc1 venv; the same numbers on 0.2.0): 50 packages fail to parse
(71 program files; the 51st, Flash-Next, was already built against a dev SDK that spells the new syntax), and once those two renames
are fixed the whole fleet parses (0 of 448 files fail) and 50 of 51 link. Everything else below is found at load time.

| Severity | Change | Fleet impact |
|---|---|---|
| HARD (parse) | `vector.constant` removed: `vector.splati` (int, predicate, index) / `vector.splatf` (float) | 71 files, 50 packages |
| HARD (parse) | `command.program.{def,decl,launch}` -> `command.{def,decl,launch}` | same files |
| HARD (load) | card `presets.*.execution.pool_capacity` rejected (`unknown model field`) | 50 of 51 cards |
| HARD (load) | `publish_epoch` gains a leading `control_state: buffer` argument (13 args) | 51 of 51 |

| HARD (deployment) | elastic shared KV pool: the server derives the pool from `--memory_bytes` (or the device's capacity); kit kernels bound `llm.pool` to 16..1048576 | 16 of 50 at 32 GiB, 36 of 50 with no `--memory_bytes` exceed the bound |
| HARD (load) | weights policy imports `weights.parameter`/`weights.input` take `key_offset, key_length` after the key (hrx-system 04aafdbe) | 8 files in 7 packages that carry a `head_weights.loom`/`draft_weights.loom` |

## 2. Breaking changes

### 2.1 `vector.constant` -> `vector.splati` / `vector.splatf` (upstream #2464)
- **Landed here**: kit emitters and checked-in programs in #986 (`starter/*`, `draft/*`, `vision/*`, reference examples); the script in #982.
- **Class**: source IR, HARD parse (`error [PARSE/006]: unknown op 'vector.constant'`, then `PARSE/001 undefined SSA value`).
- **Before / after**: `%z = vector.constant 0.0 : vector<8xf32>` -> `%z = vector.splatf 0.0 : vector<8xf32>`;
  `%m = vector.constant 252645135 : vector<4xi32>` -> `%m = vector.splati ...`. The op is chosen by the **element type**: f16, f32, f64,
  bf16, f8* -> `splatf`; i8, i32, i1 (predicate), index, offset -> `splati`. There is no compatibility spelling. Operand-driven
  `vector.splat` and the dense-list `vector.constanti [..] : vector<16xi8>` are unchanged: never rewrite `vector.constanti`.
- **Touches**: every emitter and checked-in `.loom`/`.patch` with the op: `starter/gen_llm.py`, `gen_gemm.py`, `gen_moe.py`, `quant_values.loom`,
  `draft/*`, `gen_flash2*.py`, `gen_gdn_chunk.py`, `vision/gen_vision.py`, the reference examples under `loom-port-llm/reference/` and
  `loom-optimize/reference/`. In the fleet: i32 about 7.5k, f32 5.3k, i8 2.4k, f16 0.8k sites.
- **Step**: `rewrite_v010_v020.py PATH` (packages and `.loom`/`.loom-test`/`.patch` files); `--py` for generator sources, where it rewrites
  only sites whose element type is literal and reports the rest (`vector<{n}x{ty}>`, a placeholder type) as `manual`: choose by hand.
- **Verify**: `sweep.py --sdk NEWVENV` shows no `PARSE/006`.

### 2.2 `command.program.{def,decl,launch}` -> `command.{def,decl,launch}` (upstream #2476)
- **Landed here**: kit emitters in #986; fleet tools accept both spellings (`diff_fleet.py`, `loomtext.py`, `stage_equiv.py`, #986); the script in #982.
- **Class**: source IR, HARD parse. Serialized operation ordinals are unchanged (bytecode compatible), only the text changed.
- **Touches**: emitters `starter/build.py`, `gen_llm.py`, `dual_target.py`, `f16o_fuse.py`, `draft/*`, `vision/gen_component.py`; fleet tools that
  parse programs (`fleet/diff_fleet.py`, `loomtext.py`, `stage_equiv.py`) must accept **both** spellings so base(v0.1) vs head(v0.2) diffs work.
- **Step**: `rewrite_v010_v020.py` (same pass as 2.1). **Verify**: sweep.

### 2.3 `publish_epoch` takes the retained control state first (upstream #3125)
- **Landed here**: templates `control.loom`/`service.loom` and `build_draft.py` in #986; Flash-Next gets it from the library tag (#981).
- **Class**: program ABI, HARD at model load (export signature mismatch).
- **Before / after**: `@publish_epoch(%plan: buffer, %media_plan: buffer, ...)` (12 args) ->
  `@publish_epoch(%control_state: buffer, %plan: buffer, ...)` (13 args, 0 results). `control_state` is the same borrowed buffer passed to
  `epoch`/`encode_epoch`/`encode_state`. The body may ignore it. The call from the wrappers is
  `func.call @publish_epoch(%control_state, %plan, ...) : (buffer, buffer, ...) -> ()`.
- **Touches**: `starter/templates/control.loom` (def), `templates/service.loom` (decl and the `text_`/`sequence_` `publish_epoch_v1` wrappers),
  `draft/build_draft.py` (`plain_publish_epoch` rename and wrapper), `reference/qwen4exp-example/catalog/program/text_epoch.loom`.
- **Step**: `rewrite_v010_v020.py` rewrites def, decl and call sites (any `@publish_epoch`, `@*_publish_epoch`, `@*_publish_epoch_v1` whose first
  parameter is `%plan`; already-migrated text is skipped). `--no-publish-epoch` turns it off. For a generator, change the template once.
- **Verify**: GPU smoke (serve + one chat). The sweep cannot see it (link passes either way); a signature mismatch is a load error.

### 2.4 Image component finite batch ABI (upstream #2838, #2906)
- **Landed here**: `starter/vision/gen_component.py` in #986; Flash-Next from the library tag (#981).
- **Class**: program ABI, HARD at load for packages with an image encoder (22 in the fleet).
- **Before / after** (exact text of the kit's component, `vision_control.loom`; names and bodies in between do not change):
  1. Directly after the first comment line add the three imports:

         type.decl import("finite", "batch") @FiniteBatch
         func.decl import("finite", "batch_pack") @finite_batch_pack(%batch: ptr<@FiniteBatch>) -> (buffer, buffer)
         func.decl import("finite", "batch_finish") @finite_batch_finish(%batch: ptr<@FiniteBatch>)

  2. `prepare_batch` takes the batch handle and unpacks it itself:

         - func.def public @text_image_prepare_batch_v1(%state: buffer, %tags: buffer, %ranges: buffer, %packed: buffer) -> (i32, buffer, buffer) {
         + func.def public @text_image_prepare_batch_v1(%state: buffer, %tags: buffer, %batch: ptr<@FiniteBatch>) -> (i32, buffer, buffer) {
         +   %ranges, %packed = func.call @finite_batch_pack(%batch) : (ptr<@FiniteBatch>) -> (buffer, buffer)

  3. `run` gains `%state` and `%batch` (body unchanged):

         - func.def public @text_image_run_v1(%stage: i32, %input: hal.buffer, %output: hal.buffer) {
         + func.def public @text_image_run_v1(%state: buffer, %stage: i32, %input: hal.buffer, %output: hal.buffer, %batch: ptr<@FiniteBatch>) {

  4. A **new required export** after `run` (our encoder runs one image per run, so every member is done when the run is collected; without it the
     server's "terminal offers agree with published rows" check fails):

         func.def public @text_image_collect_batch_v1(%state: buffer, %batch: ptr<@FiniteBatch>) {
           func.call @finite_batch_finish(%batch) : (ptr<@FiniteBatch>)
           func.return
         }
- **Touches**: `starter/vision/gen_component.py` and the Flash-Next package. Reference: the in-tree fixture `serve/fixture/projector/{service,control}.loom` at the new tag.
- **Step**: `rewrite_v010_v020.py` does it when the file has exactly the kit's v0.1 shape (`rewrite.json` totals `vision_abi`). Another shape (a hand-written component) is
  printed as `manual: FILE:LINE: ... section 2.4`: apply the four edits above by hand. A generator that emits these functions gets the same four edits in its template.
- **Parse and link cannot see this**: the old and the new component both parse and link (the signature is checked when the server calls the export), so `sweep.py` passes with the
  component unmigrated. Only step 7 of 3a (an image request) proves it.
- **Library catalogs are not migrated for you**: hrx-loom-library's Flash-Next `vision_control.loom` (tags v0.2.0rc1, v0.2.0 and main) has the new `prepare_batch` and `collect_batch` but still the 3-argument `run`; the 0.2.0 server answers every image request with `model export 'text_image_run_v1' argument count mismatch: host expects 5, source declares 3` (chat and drafting work, `/v1/status` shows `image.phase: failed`). Apply edit 3 to the catalog copy (`tests/test_catalog_image_abi.py` compares it with the generator).
- **Verify**: GPU smoke with one image.

### 2.5 Card: `pool_capacity` removed; elastic KV pool (upstream #2583, #3137)
- **Landed here**: writer `starter/build.py`, kernel bounds in #986; readers, card tooling, `scope.json` and fixtures in #987.
- **Class**: card schema (HARD load: `unknown model field 'pool_capacity'`) and deployment.
- **Before / after**: `presets.*.execution.pool_capacity` combined logical addressability and a per-model cache quota. Now `context_capacity` limits one
  conversation, shared physical capacity supplies the elastic ceiling, and the optional `--memory_bytes` flag (not a card key) tightens the pool-wide
  budget. The server hands the program `pool = memory_bytes / page_bytes * block` (no weights deducted). With `--pool_backing=fixed` (R9700 and Strix Halo cards)
  `pool = context_capacity`. `context_capacity` must stay a multiple of the 16-position page.
- **Touches**: writer `starter/build.py`; readers `loom-fleet/scripts/eval.sh`, `loom-benchmark/scripts/card/{card_lib,make_info}.py`, `loom-kb/choices.py`,
  scope.json files, card test fixtures, `fleet/manifest.json` `build.pool`, `fleet/regen.py`, error texts that match "increase pool_capacity" (reworded upstream).
  **Kernel bound**: kit kernels declare `config.decl @llm.pool : range(16, 1048576)` and a pool above 1048576 positions violates it at stage specialization.
  The decision is **widen** (the kit's choice in #986): the offset arithmetic is 64-bit and only page-table entries (i32, pool/16) and per-row positions are 32-bit,
  and DevLab proved it with the sdk020 sweep's `attention_bigpool` kernel test (K/V written and read through a pool of 5.08 M positions, byte offsets past 2^31). Do not cap with `--memory_bytes` instead. The bound is not one number; four
  kinds of line move together, and the script matches each by its op and symbol, never by the bare number:

  | line (v0.1) | after | rule |
  |---|---|---|
  | `%pool = index.assume %pool_arg [range(%pool_arg, 16, 1048576)]` (every kernel with a pool argument) | `..., 16, 2147483584)` | `index.assume` of a `%*pool*` value |
  | `config.decl @llm.pool : %value: index where [range(%value, 16, 1048576)]` | `..., 16, 2147483584)` | the `@llm.pool` config |
  | `%bounded_physical = scalar.assume %physical32 [range(%physical32, 0, 1048575)]` (also `%kh_ph32`) | `..., 0, 134217727)` | `scalar.assume` of a `%*physical*` / `%*_ph*` page id (pages = pool/16) |
  | flash2 `index.assume %v [range(%v, 0, 1048560), lt(%v, %pl_rows_m)]` / `[range(%v, 0, 1048575), lt(%v, %pool)]` | `2147483568` / `2147483583` | `index.assume` with those two `lt` companions |

  A 1048575 or 1048576 anywhere else (resident-row bounds such as `%bounded_row ... range(%row, 0, 1048575)`, `%bounded_rows ... range(%rows, 1, 1048576)`, an `index.constant 1048576`)
  is not a pool bound and stays: the script leaves it. `--no-widen-pool` skips the whole class. `multiple_of(64)` (upstream's spelling) is not adopted: the kit's page is 16 positions.
- **Step**: `rewrite_v010_v020.py` removes `pool_capacity` from `model.json` (formatting kept) and widens the four kinds above (`rewrite.json` totals `pool_arg`, `pool_decl`,
  `physical_page`, `flash2_rows`); writers stop emitting the key; readers tolerate its absence.
- **Verify**: `sweep.py` link with the card config; GPU smoke with and without `--memory_bytes`.

### 2.8 Weights policy imports take a key range (upstream 04aafdbe, hrx-loom-library companion)
- **Landed here**: `starter/draft/prep_weights.py` in #986 (7 packages carry the policy files); the script in #982.
- **Class**: program ABI, HARD at load; **invisible to the parse sweep** (decl and calls are consistent in an old package, and the files sit at the
  package root as `data` inputs of `prepare.loom`, outside `program/`). `sweep.py` parses `data` `.loom` inputs, but only a server load shows the mismatch.
- **Before / after**: `@parameter(%source: i32, %key: buffer) -> (buffer, i64)` -> `@parameter(%source, %key, %key_offset: i64, %key_length: i64)`;
  `@input(%source, %key, %offset, %length, %alignment)` -> `@input(%source, %key, %key_offset, %key_length, %offset, %length, %alignment)`. The key is a range of a reusable
  buffer; for a whole-buffer key pass offset 0 and `buffer.length` converted with `index.cast %n : offset to i64` (the library's `Qwen3-Embedding-0.6B/program/policy.loom` does this).
- **Touches**: `starter/draft/prep_weights.py` (the decl and the call, emitted into `head_weights.loom` and `draft_weights.loom`).
- **Step**: `rewrite_v010_v020.py` rewrites the decl and each `func.call @input`/`@parameter` of the weights policy (adds three lines before the call); with `--py` only the decl
  text of a generator, so change the emitter's call by hand to produce the same three lines. **Verify**: after the decl is migrated an unmigrated call fails to parse
  (`STRUCTURE/001 'func.call' has 5 operands, expected 7`); then a GPU smoke of a package that has a weight policy.

### 2.9 One-token conv index guard (v0.2 compiler)
- **Landed here**: the GDN helper `gen_gdn.py` and the LFM2-MoE `gen_sconv.py` in #986 (18 fleet packages carry the guarded helper).
- **Class**: JIT-time failure in specialization, not a parse or link error. Seen upstream on Qwen3.8-27B and MiniCPM OCR; the fix is an added `token >= back` guard in
  the conv-state indexing of the one-token specialization (the kit's GDN and short-conv helpers; `rel >= back` alone does not prove `token >= back`).
- **How to detect the helper**: `grep -n 'uge, %rel, %back' PKG/program/*.loom` (a recurrent package: Qwen3.5/3.8 GDN, LFM2 short conv; a dense or vision-only package has none).
  `rewrite_v010_v020.py` finds it itself and reports it (`rewrite.json` total `conv_guard`).
- **Before / after** (one tap per `index`; the helper repeats it per tap and unroll):

      - %has0_u0 = index.cmp uge, %rel, %back0_u0 : index
      + %has_rel0_u0 = index.cmp uge, %rel, %back0_u0 : index
      + %has_token0_u0 = index.cmp uge, %token, %back0_u0 : index
      + %has0_u0 = scalar.andi %has_rel0_u0, %has_token0_u0 : i1
- **Step**: the script rewrites every `%hasN = index.cmp uge, %rel, %backN` whose `%backN` is then used in `index.sub %token, %backN`. A `uge, %rel, %back` line of another shape is
  printed as `manual: FILE:LINE: ... section 2.9`: add the `%token` comparison and AND it by hand.
- **Verify**: serve a hybrid recurrent package (decode exercises the one-token path); a JIT error at the first decode is this.

### 2.10 rc1 -> 0.2.0 (what changed between the candidate this entry was developed on and the stable release; no migration step)
Nothing here breaks a package migrated for rc1; the migration (sections 2 to 3) is the same for 0.2.0. Re-verified on the 51-package fleet: `sweep.py` parse 0 of 448 files fail and
link 50 of 51 on both rc1 and 0.2.0; `fleet/link_check.py` 50 of 51 plus the Flash-Next exception. Details and evidence: the campaign's `notes/sdk020_research.md` section 7.
- **Surface**: every CLI's `--help` is byte-identical; the wheel has the same files (3 Python docstring/validation texts differ); the model-card schema, `loom-serve` flags and defaults (wait mode,
  pool, `completion_spin_ns`) are unchanged (no diff for `pool_backing`, `wait_mode`, `context_capacity`, `memory_bytes` in range). `loom.json` names the catalog `github:ROCm/hrx-loom-library@v0.2.0`.
- **One new API row**: `loom_runtime_host_create(worker_count, NULL, compiler_options, ...)` (a `processor_set` argument: native C embedders only; the host's CPU budget now covers Task and I/O workers,
  so a server under `taskset`/cpuset stays inside it). Nothing in this repo calls it.
- **Codegen index-arithmetic repairs** (signed index carriers keep both signs, narrow i32 observations stay native, vector coordinate/slice bounds are retained through shape lowering, uniform wide index
  mul/mad/shl stay in scalar registers): JIT/codegen only, no source change. The documented contract is now that `vector.extract/insert/slice` coordinates are nonnegative and inside the axis;
  a program that violated it is diagnosed or compiled differently. Float numerics do not change by design; clustered float sums may select XOR trees (#3291), so last-ulp differences can appear: the golden near-tie gates
  decide. A kernel failure seen on rc1 that is an index-width bug (the fleet's one: Ornith-122B `moe_gemm_12` on Strix) may be fixed; re-run it before listing it as a known failure.
- **Perf-relevant, measure not assume**: resident-shader recorded transfers 64 KiB to 1 MiB (#3302), load elision (XDNA only, no effect on GPU serving), scalar-register index arithmetic (AMDGPU kernels). All numbers on cards are 0.2.0
  numbers, never rc1 (rc1 runs are pilot data).
- **Distribution**: 0.2.0 is on PyPI, so the pin source is `pypi` and the card Quick start is `pipx install "hrx-loom[hf]==0.2.0"` (no release-wheel URL, no pre-release note); the installer keeps the `release` source for the next pre-release.
- **Flash-Next catalog**: the library moved rc1 -> v0.2.0 with no change to any file the catalog uses, so `library_delta.patch` applies unchanged and flattening reproduces the checked-in catalog byte for byte; only the pin changed.
  The pristine library model still fails our joint link (`SYMBOL/013`) as on rc1.

## 3. Mechanical steps

### 3a. One package you own (programs plus `model.json`, hand-made or a catalog package; no GPU needed until step 6)

A package generated by this repo's kit: do NOT rewrite it, regenerate it with the kit at `sdk020` or later (the kit emits v0.2 text, the pin and
the widened pool bounds). Everything below is for a package the kit did not produce.

    export LOOM_SKILL_DIR=/absolute/path/to/loom-skills/skills/loom-migrate     # this skill's directory (Claude Code: export LOOM_SKILL_DIR="${CLAUDE_SKILL_DIR}")
    export LOOM_SETUP_DIR=/absolute/path/to/loom-skills/skills/loom-setup       # its sibling
    PKG=/path/to/package        # the directory with model.json and program/
    # 1. install the new SDK (PyPI, wheel sha256 recorded) into its own root, next to the old one
    bash "$LOOM_SETUP_DIR/scripts/install_loom.sh" ~/loom020 0.2.0      # venv ~/loom020/.venv; ~/loom020/loom-install.json is the pin
    NEW=~/loom020/.venv
    # 2. keep a copy of the old package: the old SDK still serves it, and it is the A/B baseline
    cp -a "$PKG" "$PKG.v010"
    # 3. what would change; then apply (idempotent). --check exits 1 while anything would change (verified: 1 on a v0.1 package, 0 after the apply)
    python3 "$LOOM_SKILL_DIR/scripts/rewrite_v010_v020.py" --check "$PKG"; echo "check exit $?"
    python3 "$LOOM_SKILL_DIR/scripts/rewrite_v010_v020.py" "$PKG" --json rewrite.json
    python3 "$LOOM_SKILL_DIR/scripts/rewrite_v010_v020.py" --check "$PKG"; echo "check exit $? (want 0)"     # prints "would change 0"
    # 4. the script does 2.1 to 2.5, 2.8, 2.9 (the pool bounds, the conv guard and the vision ABI included). Read what it prints:
    #    every `manual: FILE:LINE: ... section N` line is one hand edit in that section of this entry; no manual line, nothing to do.
    #    Only a generator placeholder (a vector.constant whose element type is a template variable) and a component of another shape end up there.
    # 5. offline proof under the new SDK: every program file and data input parses, every variant links
    python3 "$LOOM_SKILL_DIR/scripts/sweep.py" --sdk "$NEW" "$PKG" --json sweep.json     # want: 0 fail to parse, 0 fail to link
    # 6. stamp the SDK pin so a loader knows which SDK the package needs (a package with no pin means 0.1.0); needs an llm_config.json in the package
    python3 "$LOOM_SETUP_DIR/scripts/sdk_pin.py" stamp ~/loom020 "$PKG/llm_config.json"
    # 7. serve on the new SDK and chat (needs a GPU; MEMORY_BYTES is an upper bound on weights + KV pool + workspace)
    VENV=~/loom020/.venv bash "$LOOM_SETUP_DIR/scripts/serve.sh" mig 8100 amdgpu 16000000000 "$PKG/model.json"
    MODEL_ID=$(curl -s localhost:8100/v1/models | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"][0]["id"])')
    curl -s localhost:8100/v1/chat/completions -H 'Content-Type: application/json' \
      -d "{\"model\":\"$MODEL_ID\",\"messages\":[{\"role\":\"user\",\"content\":\"Say hi\"}],\"max_tokens\":16}"
    #    a package with an image encoder: ALSO send an image (this is the only proof of 2.4; the first image request runs prepare_batch, run and collect_batch)
    IMG=$(base64 -w0 /path/to/photo.png)
    curl -s localhost:8100/v1/chat/completions -H 'Content-Type: application/json' \
      -d "{\"model\":\"$MODEL_ID\",\"messages\":[{\"role\":\"user\",\"content\":[{\"type\":\"text\",\"text\":\"Describe the image.\"},{\"type\":\"image_url\",\"image_url\":{\"url\":\"data:image/png;base64,$IMG\"}}]}],\"max_tokens\":48}"
    bash "$LOOM_SETUP_DIR/scripts/stop.sh" mig

`~/loom020` is the SDK root of this recipe, so the 0.1.0 install in `~/loom` (what `loom/SKILL.md` assumes) keeps serving the old package; pass any other root as the
first argument of `install_loom.sh` and the same path in `VENV=` and `sdk_pin.py`. **Parse and link cannot see ABI errors**: `sweep.py` passes (0 and 0) on a package whose
image component (2.4) or `publish_epoch` signature (2.3) is wrong, because those signatures are checked when the server loads and calls the export. The serve smoke of step 7 is
required, not optional; without a GPU, say that the package is "parses and links, not load-tested".

What a failure at each step means: a parse error at step 5 is the first error of section 9 (fix the first one, the cascade goes); a link failure is a load
failure on a GPU; an error at step 7 naming a signature (`publish_epoch`, `text_image_*`, a weights policy import) is one of 2.3, 2.4, 2.8; `unknown model
field` is 2.5; a JIT error in a recurrent package is 2.9.

## 6. Behaviour changes to measure
- Decode: launch work (one-packet AQL, scalar PM4 copies, warm recordings) should help small, launch-bound models and be neutral on large ones.
- Prefill and TTFT: mixed prefill/decode scheduling was rewritten (`packing.c`, `epoch.c`), so 4-stream and TTFT can move either way.
- Completion policy: the default active wait is now 1 s renewing; our explicit URI overrides it. Compare default vs explicit (ledger item).
- Requests: `stop`, `n`, `logprobs`, `frequency_penalty`, `parallel_tool_calls`, `user` were HTTP 400 and are now ignored; there is no stop-sequence handling in the native
  text service in either version (only EOS and `max_tokens`). `tool_choice=none` no longer suppresses tool calls (the server parses tool text whenever `tools` is non-empty).
  Wrongly typed `temperature/top_p/top_k/seed` are skipped, not 400. `max_completion_tokens` wins over `max_tokens`; the cap is INT32_MAX (was 16384).
  Kit `request_options` reads only number-typed sampling fields; `chat_template_kwargs`/`enable_thinking` are read by the kit's `chat_begin`, not natively.

## 9. Gotchas
- `unknown op 'vector.constant'` then a cascade of `undefined SSA value` -> the op was split by element type -> `rewrite_v010_v020.py`; fix the first error and the cascade goes.
- A rewrite that touches `vector.constanti` breaks the dense-list op -> it is unchanged in v0.2 -> the regex requires whitespace after `constant`.
- `unknown model field 'pool_capacity'` at serve, `KeyError: 'pool_capacity'` in eval/card scripts -> the card schema dropped it -> remove from writers, tolerate absence in readers.
- A package serves on 0.1.0 but fails at load on the new SDK with a `publish_epoch` signature error -> the leading `control_state` argument -> rewrite (2.3).
- `fleet/link_check.py` truncated `@qwen38.packet_capacity` to `@qwen38` and reported `SYMBOL/017 root symbol has no definition` -> its root regex used `\w+` -> match `[\w.]+` (sweep.py does).
- `SYMBOL/013 ... incompatible contract field 'symbol interfaces'` on Flash-Next after the renames -> its checked-in programs are library-derived (dev SDK pin) and their config contract does not link under rc1 -> refresh them from the library tag instead of rewriting.
- `git fetch origin v0.2.0` then `git checkout v0.2.0` fails in an existing catalog clone -> a plain fetch of a tag leaves only `FETCH_HEAD` -> `git fetch origin tag v0.2.0` or check out `FETCH_HEAD`.
- `pip install hrx-loom==0.2.0rc1` finds nothing -> a pre-release is only a GitHub release asset (it was true of rc1; 0.2.0 is on PyPI) -> `install_loom.sh ROOT 0.2.0rc1` or the wheel URL with its sha256.
- `loom-opt --version` is not a flag -> read the version with `python -c "import importlib.metadata as m; print(m.version('hrx-loom'))"` in the venv (`loom-serve --version` exists in v0.2).
- Kernel A/B timings differ from last month's -> `loom-test` moved off `legacy-amdgpu` to the libamdf HAL -> re-baseline both sides in one job.
- A weights policy (`head_weights.loom`) passes the parse sweep on the old fleet and fails only at load -> its import signature changed (2.8) and the file is a `data` input at the package root -> rewrite, and sweep the data inputs too.
- Kit-generated packages fail `dual_target` "cannot read the program header" after the rename -> the generators' regexes spell `command\.program\.def` with an escaped dot, so a plain-text search misses them -> grep `command\\.program` too and rewrite the regexes (`dual_target.py`, `gen_llm.py`).
- A blind `sed` of `vector.constant` picks the wrong op -> the element type decides `splatf` (f16/f32/bf16/f8) vs `splati`, and templated types (`: {vec}`, `: {ty}`, `: {vt}`) are invisible in the text -> the script reports them `manual`; in the kit they were all float constants (`splatf`).
- Every kernel of a v0.1 vs v0.2 fleet diff differs -> the spellings differ -> compare in one spelling (`diff_fleet`, `stage_equiv`, `loomtext` read both; `--raw-spelling` shows the renames); `stage_equiv` must upgrade the base text before the v0.2 `loom-opt` parses it.
- Widening `llm.pool` to one number breaks specialization -> physical-page assumption, flash2 row ranges and every `%pool_arg` assume share the bound -> widen them together (2.5; the script does, by op and symbol, and leaves the unrelated 1048575/1048576 row bounds).
- `sweep.py` reports 0 and 0 on a package with a v0.1 image component or `publish_epoch` -> the signatures are checked at load -> parse and link prove syntax only; serve it and send an image (3a step 7).
- A regression test for "exact link selection" passes silently on v0.2 -> `loom-link` no longer fails a key defined (`config.def`) in several inputs -> inject a key declared as a func (`SYMBOL/020`) to get a real offline link failure.
- Ten tool-driven tests fail with v0.1 `loom-opt` first on PATH -> v0.2 text does not parse there -> put the 0.2.0 venv `bin` first (or set `LOOM_LINK`/`LOOM_OPT`); the hard-coded `~/lt/loom010` fallbacks are gone. The same venv needs gguf, jinja2, numpy and pyyaml for the tests.
- A new env var in a starter script fails `tests/test_choices` -> every env var must be registered -> do not add an env knob for a one-off case.
- Weights policy `input(...)` gained `key_offset`/`key_length` (04aafdbe) and the files sit at the package root -> only the 7 packages with a `prep_weights` policy are affected, outside `program/` (2.8).
- One-token specialization of the GDN/short-conv helper -> `rel >= back` alone does not prove `token >= back` -> add `index.cmp uge %token, %back` and AND it (2.9; the script does, `grep 'uge, %rel, %back'` shows the helper).
- hrx-loom-library packages (Flash-Next): the joint link of all inputs fails `SYMBOL/013` (config key vs func `qwen38.packet_capacity`) on the unmodified `v0.2.0rc1` and `v0.2.0` tags; linking each input separately with the service config passes -> `link_check` stays joint and lists it as an exception; also its roots regex needs dotted names. The library tag brings about 60 commits of kernel work with the SDK bump, so its A/B measures both.
- Card test `check.sh` dies silently after its first line -> `bench_common` imports `requests`, which the bare 0.2.0 venv lacks (stderr is discarded) -> run `check.sh` with the system python3; only the unit tests want the new venv first.
- `scope_lint` kind `tooling` rejects `render_card`/`make_info`/`card_lib`/`info_schema`/`check.sh` and goldens ("protected core file (card schema)") -> card-tooling PRs declare `kind: architecture`; run `scope_lint --local --base origin/sdk020 --work DIR_ON_DISK` (default base is `origin/refactor`, default work dir is /tmp) from a venv with gguf, jinja2, numpy and pyyaml.
- A fit row whose only R9700 execution setting was `pool_capacity` loses its `r9700_execution` block once the key leaves `EXEC_KEYS` -> `tests/test_scopegaps` compares against the stripped "before" table.
- `loom-fetch huggingface:ORG/REPO` fails "select explicitly (N choices)" for a multi-preset card (also the raw URL) -> name the preset: `huggingface:ORG/REPO:PRESET` (cards always do when the facts have several).
- Fleet A/B old side measured an older card than the one live -> `fleet/manifest.json` `staging.revision` lags the staging heads (11/51 heads had newer programs) -> pin the old side to the staging head at plan time (`regen.py --mode sdk-ab` does since #1033); when the heads already carry new programs, pin it to the newest revision before the migration upload.
- A job's programs hash never matches the published package -> the in-job build differed from the canonical one: a fit-context or other memory budget (card context and `--memory-gib 4096` are canonical) and the runner's path in the generated-by comment of `llm.loom` -> build in the job exactly as `fleet/build_fleet.py` does (#1016) and keep build paths out of program text (#1017); compare `programs_sha256` of job and canonical build before ingesting.
- Cards published with the old SDK pin in the Quick start although the package was migrated -> the package step skipped heads whose programs already equalled the canonical build (rc1 and 0.2.0 emit identical programs), so `llm_config.json`'s pin was never refreshed -> skip only when the head holds the WHOLE package (programs, `llm_config.json`, `model.json`) (#1099).
- A confirmed slowdown blocks a card forever -> the ratchet holds it in `needs_decision` -> once the cause is written up, `regen.py accept-regression --note "..." STATE SLUG` publishes the measured numbers (the delta line keeps the negative values); gate failures and degraded runners are never accepted this way.
- A model held only by kernel tests that ran and failed for an explained reason (the same case failed on the previous SDK's card) stays held -> `regen.py accept-gate-failure --note "..." STATE SLUG` publishes it with the kernel tests shown as failed in the gate table; func and serving gates, and kernel tests that did not run, are never accepted.
- Job builds without `--slug` miss the knowledge base's slug-matched model choices (Qwen3.8-27B lost its proposal-head copy: decode -10 %; Qwen3.6-35B-A3B built other programs than the canonical package) -> every in-job build passes the card's slug, as `fleet/build_fleet.py` does (#1131); compare the job's built hash with the fetched head for every job before trusting a slowdown.
- Strix Halo prefill is 5-8 % slower on 0.2.0 than on 0.1.0 (small models most, plus a 3-request ramp) when served with `--memory_bytes` -> 0.2.0's elastic state backing costs steady prefill; this is expected behaviour per the owner, not an SDK bug to fix here -> cards serve `--pool_backing=fixed` on every GPU (`skills/loom-kb/device/rdna3/strix-halo/device.json` `card.serve_args`, as the R9700 always did); fixed commits the preset's `context_capacity` KV and the weights eagerly, so `--memory_bytes` stays only for the elastic option (several models sharing one budget). In a DevLab A/B the old v0.1.0 card is then served fixed too (its `pool_capacity` committed eagerly): an old-card variant that must reproduce its elastic-era card rows sets `"elastic": true`.
- R9700 cards that fit on 0.1.0 fail at the first request on 0.2.0 (`RESOURCE_EXHAUSTED`, image or drafter component `unavailable`) -> 0.2.0 allocates its automatic prefix/session caches (`cache_target_bytes`, default 2 GiB) eagerly under `--pool_backing=fixed` -> a smaller `exec.cache_target_bytes` in the model's R9700 rule (512 MiB for Flint and Muse-Glimmer-30B, #1133).
- A library catalog package serves chat but every image request fails `text_image_run_v1 argument count mismatch: host expects 5, source declares 3` -> the library's Flash-Next `vision_control.loom` (v0.2.0) still has the 3-argument `run` -> apply edit 3 of 2.4 to the catalog copy (#1137).
